# 열공 · 문장 사이를 읽다

전체 시험 범위 115개 지문, 829문장을 공부하는 정적 웹사이트입니다. 기존 독해 108지문에 「캐서린의 어법 Finish」의 2020~2026학년도 수능 29번 7지문을 특별 영역으로 추가했습니다. 주장·함축 의미·어휘·무관한 문장·글의 순서는 각 8개, 요지·제목은 각 15개, 빈칸은 38개입니다. 과거에 범위에서 제외한 어법 유형 8지문은 복구하지 않았습니다.

## 실행

압축을 풀고 `index.html`을 브라우저로 열면 됩니다. 태블릿에서는 GitHub Pages 등 정적 호스팅에 폴더 내용을 그대로 올려 사용하는 방법이 편합니다. 서버, API 키, 패키지 설치와 빌드가 필요하지 않습니다.

로컬 웹 서버가 필요한 경우 이 폴더에서 `python -m http.server 8765`를 실행하고 `http://localhost:8765`를 엽니다. `file://`에서의 저장 지원은 브라우저에 따라 다를 수 있습니다.

## 학습 방법

- 목록에서 원래 출제 유형으로 고르거나 제목·주제·출처를 검색합니다.
- **지문 분석**: 전체 흐름 → 쉬운 설명 → 문장 연결 → 전환·범위 → 지시·구문 → 핵심 정리 순으로 읽습니다. 요청한 12개 분석 항목을 이 여섯 목차에 묶었습니다.
- **수능 유형 대비**: 예상 주제·요지·제목, 순서 구획, 삽입·빈칸 후보와 근거, 주요 어법·어휘를 확인합니다. 새로운 문제나 선지를 만들지 않았습니다. 예상 표현은 학습용 제안이며 공식 답안이 아닙니다.
- **어법 특별**: 기본 화면은 어법 집중 분석입니다. 밑줄 ①~⑤ 모두에 판단 근거와 오답 형태의 함정을 설명하고 유형별 판단 순서를 제공합니다. 내용·문장 연결 탭에서는 간단한 이해와 모든 문장의 앞뒤 연결을 확인합니다. 원문 아래 직역과 개인 기록은 동일하게 유지됩니다.
- 기존 108지문의 **어법·어휘**에는 지문마다 대표 어법 요소 한 곳을 골라 특별 자료와 연결했습니다. 총 108개 연결 해설이며, 각 지문의 모든 어법을 망라한 목록은 아닙니다. 원래 구문·어휘 해설도 함께 유지합니다.
- 원문의 모든 영어 문장 아래에 한글 직역을 표시합니다. 직역 보기·숨기기 설정은 저장됩니다. 쉬운 설명은 지문 내용을 일상적인 말로 풀어 논리 연결을 이해하도록 돕습니다.
- 원문 문장을 누르면 해석과 연결 설명으로, 해설의 S 번호를 누르면 원문 강조 위치로 이동합니다.
- 태블릿 가로·세로에서는 원문과 해설을 나란히 독립적으로 스크롤합니다. 작은 화면에서는 위아래로 배치됩니다.
- 보관, 학습 완료, 메모, 원문 글자 크기는 현재 브라우저에 자동 저장됩니다. 다른 기기로 동기화되지는 않습니다. 브라우저 데이터를 지우면 기록도 사라집니다.

## 원문 처리

`assets/sources/00.jpg`부터 `47.jpg`까지 사진을 제공합니다. 기존 사진은 읽기용 사본이고, 추가 사진 22~47은 제공된 원본입니다. 사진 번호는 화면에서 1부터 표시합니다. 의도적으로 흰색 처리된 내용은 복원하지 않았습니다. 사진 경계를 넘는 지문은 겹치는 내용을 확인하고 연결했습니다.

`48.jpg`~`54.jpg`는 어법 PDF 4~10쪽의 읽기용 이미지입니다. 개요에 중복된 지문은 다시 넣지 않았습니다. 특별 자료의 영문은 원래 출제 오류를 보존하며 직역은 교정한 의미입니다. 문장 S 번호와 밑줄 ①~⑤ 번호를 구분합니다.

S1, S2는 학습용 문장 번호이며 원래 문제의 ①~⑤와 다릅니다. 원래 문제 정답 해설에서는 원래 선지 번호를 사용합니다.

- 어휘: 원문의 출제 오류를 유지하고 밑줄 표시했습니다. 교정과 이유를 함께 제시하며, 번역은 교정된 의미를 반영합니다.
- 빈칸: 정답 표현을 채운 학습용 본문을 제공하고 해당 표현을 색으로 표시합니다. 원래 빈칸은 사진에서 확인할 수 있습니다.
- 무관한 문장: 원문과 문장별 분석에는 보존하고, 순서 학습 구획에서는 제외합니다.
- 순서: 정답에 해당하는 읽기 순서로 본문을 연결하되, 주어진 글과 원래 A/B/C 표기를 보존합니다.
- 사진에 있는 기존 문제 해설은 지문 독해에 근거하여 작성했습니다. 별도의 공식 정답표를 연결한 자료는 아닙니다.

## 파일 구조

```text
index.html              화면의 껍데기
style.css               태블릿 반응형 스타일
script.js               탐색, 두 영역 렌더링, 학습 기록
 data/index.js          가벼운 목록과 메타데이터
 data/exams/claim.js     주장 본문 및 분석
 data/exams/inference.js 함축 의미 본문 및 분석
 data/exams/gist.js      요지 본문 및 분석
 data/exams/title.js     제목 본문 및 분석
 data/exams/blank.js     빈칸 본문 및 분석
 data/exams/vocabulary.js 어휘 본문 및 분석
 data/exams/coherence.js 무관한 문장 본문 및 분석
 data/exams/sequence.js  순서 본문 및 분석
 data/exams/grammar-special.js 어법 특별 7지문 및 밑줄 35곳 분석
assets/sources/          사진 사본
scripts/reindex.cjs      자료 추가 후 목록 재생성
scripts/validate.cjs     데이터 정합성 검사
```

목록과 본문은 분리되어 있습니다. 지문을 열 때 그 유형의 본문 파일만 불러옵니다. 외부 라이브러리·폰트·분석 서비스에 의존하지 않습니다. 예전 시험 자료는 새 목록과 본문에서 제거했습니다.

## 지문 추가

1. 해당 `data/exams/*.js`의 배열에 지문 객체를 추가합니다. 기존 지문의 `id`는 학습 기록 키이므로 변경하지 마세요. 새 유형은 같은 등록 형식의 파일을 하나 만듭니다.
2. 사진을 `assets/sources/`에 추가하고 `photos`에 번호를 넣습니다. 배열은 파일 이름의 0부터 시작하는 숫자를 사용합니다.
3. Node.js가 있다면 `node scripts/reindex.cjs`로 목록을 재생성하고 `node scripts/validate.cjs`로 검사합니다. 런타임에는 Node.js가 필요 없습니다.
4. 변경한 파일과 재생성된 `data/index.js`를 함께 호스팅에 반영합니다.

주요 데이터 필드:

| 필드 | 내용 |
| --- | --- |
| `id`, `num`, `type`, `title`, `source`, `photos` | 고유 ID, 유형 내 번호, 유형, 제목, 출처, 사진 번호 |
| `sentences` | `{n,en,ko,literal,role,why}`: 원문, 자연스러운 해석, 원문 아래 직역, 기능, 앞뒤 연결 이유 |
| `easy` | 상황과 논리 연결을 쉽게 풀어 쓴 문단 배열 |
| `flow` | 4~7개의 `[단계 이름, 시작 S, 끝 S, 이 단계가 나오는 이유]` |
| `connectors` | `[S 번호, 연결 표현, 이전 논리, 이후 논리]` |
| `compare` | `[비교 대상 1, 비교 대상 2, 비교 축, 차이 설명]` |
| `refs`, `syntax` | 지시어 선행사 및 필요한 문장 구조 분석 |
| `turns` | 핵심 전환 문장의 S 번호 배열 |
| `central`, `tip`, `topicEN`, `titleEN` | 중심 주장, 읽기 포인트, 예상 주제·제목 |
| `order` | `[시작 S, 끝 S, 덩어리 설명]` 세 구획 |
| `insert`, `blank` | 삽입 후보 `[S,근거]`, 빈칸 후보 `[S,원문 그대로의 표현,근거]` |
| `vocab`, `answer` | 어휘와 논리 역할, 원래 문제의 판단 근거 |
| `edits` | 선택: `[S,출제 오류 표현,교정 표현,이유]` |
| `grammarLinks` | 기존 지문의 연결 어법: `{n,category,quote,rule,trap,from}`. from은 특별 지문 ID |
| `specialGrammar`, `grammarPoints`, `sourcePage` | 특별 영역 여부, 밑줄 5곳 해설, PDF 원본 페이지. grammarPoints는 연결 어법 필드에 `number`, `replacement`를 더함 |
| `irrelevant` | 선택: 흐름과 무관한 S 번호 |
| `sequence`, `introCount` | 선택: 원래 단락의 올바른 순서, 주어진 글 문장 수 |

문장 범위는 모두 1부터 시작하며 끝 번호를 포함합니다. 순서 구획은 주어진 글과 무관한 문장을 제외한 본문 전체를 빠짐없이 포함해야 합니다.

특별 지문은 일반 지문의 순서·빈칸·선지 분석 필드 대신 `grammarPoints`를 사용합니다. 각 밑줄의 원문 인용과 교정 한 곳을 검사합니다. 배포 시에는 `index.html`의 정적 파일 버전과 `script.js`의 본문 파일 버전 문자열도 함께 올려 이전 캐시가 섞이지 않도록 합니다.
